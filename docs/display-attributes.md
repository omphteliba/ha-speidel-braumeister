# Current-step display attributes

The `current_step` sensor exposes firmware display context in addition to its
translated state. These attributes describe the reported screen; they do not
change command authorization or canonical process, alarm, pump, or heater states.

| Attribute | Source and meaning |
| --- | --- |
| `display_clock` | Field 1, validated H:MM or HH:MM device clock |
| `display_pump_flag` | First character of field 14 (`P`, `p`, `q`) |
| `display_heater_flag` | Second character of field 14 (`H`, `h`, `i`) |
| `display_time_target_seconds` | Field 6 on timed-rest screens 2810–2909 and screen 3010 |
| `display_time_elapsed_seconds` | Field 7 on the same timed screens |
| `display_button_labels` | Field 13, raw button context |
| `display_editor_flags` | Field 15, raw editor/interrupt context |
| `display_start_delay_seconds` | Field 17 on 2120/A00S/000, nonnegative countdown capped at 2147483647 |

Invalid clocks or actuator pairs and unavailable/negative display timers return
`None`. Countdown values outside 0–2147483647 or outside the exact countdown
context return `None`. Missing button/editor fields are empty strings. Raw flags
are preserved rather than interpreting every flag combination as a supported action.

In particular, the Display Card needs `0D0`/`0DT` to distinguish a lid warning
from a generic pause: both can have `display_interrupt=1`. The raw context lets
the card select the lid-confirmation action instead of a generic resume action.
The Bridge remains responsible for validating every command.

The existing `process_status.start_delay_seconds`, pre-start classification,
recipe handling, and service capabilities remain unchanged. A timer is deliberately
not inferred for other screens from potentially stale fields 6 and 7.

## Offline validation (2026-11-19)

Base: upstream `a2e005f`. Consumer: released Display Card `0.7.0-beta.37` bundle.
Parser boundary tests cover clocks, actuator pairs, editor context, live timer
changes, missing fields, and countdown validation. HA tests verify the actual
current-step sensor attributes and unchanged process-status attributes.

An isolated Node harness consumed JSON generated by the new Python parser and
loaded the released card with a minimal DOM shim. Seven scenarios passed: lid,
lid editor, pause, heating, time editor, countdown, and main menu. Assertions
covered action selection, device clock, timer rendering, and removal of stale
timer/countdown content. No HA service or device command was sent. This is a
contract/rendering check, not a real-browser or live-hardware test.
